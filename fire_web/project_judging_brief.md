# 慧焰導行 – 室內火災智慧逃生系統 評審出圖簡報底稿

## 1. 作品定位
- 作品名稱：慧焰導行 – 室內火災智慧逃生系統
- 英文名稱：Smart Indoor Fire Escape System (SIFES)
- 副標題：即時感測 × AI 路徑規劃 × 視覺化逃生指引，讓每個人都能活著走出去
- 類型：IoT / AI / Web / 安全 / 教育
- 目標使用者：學校師生、辦公室人員、任何室內空間的建築物使用者
- 使用場景：教室、電腦室、辦公室發生火災時，系統即時分析火勢分布，提供最佳逃生路線或避難指引
- 一句話介紹：當火災發生時，系統透過火焰感測器即時掌握教室內火勢分布，以 A* 演算法計算避開危險區域的最佳逃生路線，並透過 AI 生成直觀的視覺化逃生圖，指引使用者安全離開或就地避難。

## 2. 問題與價值
### 核心問題
室內火災發生時，濃煙和高溫會嚴重干擾視野與判斷力。多數人因恐慌而無法在幾秒鐘內決定往哪裡跑，現有的消防逃生圖只是靜態平面圖，完全無法反映火源位置與即時危險分布。因逃生方向錯誤而導致的傷亡，遠遠高於火勢本身造成的直接傷害。

### 現有方案不足
- **傳統逃生平面圖**：只是貼在牆上的靜態紙本，無法反映火源位置、火勢蔓延方向
- **消防警報系統**：只能發出警報聲響，無法告知「往哪裡逃最安全」
- **紅外線熱像儀**：造價昂貴、需專業人員操作，無法普及到一般教室/辦公室
- **現有智慧逃生系統**：多數依賴大量固定式煙霧感測器 + 中央控制系統，佈建成本極高，且無法動態規劃個人最佳路線

### 本作品價值
- 以**低成本火焰感測器 + Arduino + Web 技術**實現即時火勢分布感測
- 透過 **A* 路徑規劃演算法**在幾毫秒內計算出避開高危險區域的最短路線
- 結合 **AI 生成式模型（Nano Banana / Gemini）** 在真實課室平面圖上疊加熱力圖和逃生路線，輸出直觀、人人都看得懂的逃生圖
- 當逃生路徑全部被封鎖時，系統會自動**計算出最安全的避難位置**，並觸發 SOS 警報
- 整組系統可透過 **PWA（漸進式網頁應用）** 在手機上打開，不需安裝 App

## 3. 作品故事線
### 代表性情境
某日下午，學校電腦室突然發生火災。火源從教室右上方（近出口處）開始蔓延，濃煙迅速擴散。教室內有 5 名學生，左下角位置最遠離火源。

### 使用流程（5-7 步）
1. **火災發生**：教室內 5 個火焰感測器即時偵測到不同位置的火焰強度（0-255 亮度值）
2. **數據彙集**：Arduino Uno 透過 USB 串列通訊將 5 個感測器數值即時傳送至 Web Server（每 200ms 更新一次）
3. **危險熱力圖生成**：後端將 5 個感測器值轉換為 4×4 危險矩陣，再透過雙線性插值放大為 20×20 精細網格，生成熱力圖
4. **考慮障礙物**：系統載入教室平面圖中的桌子/障礙物分布遮罩（20×20 網格），確保路線不會穿越桌子區域
5. **A* 路徑規劃**：演算法從左下角起點到右上角出口，計算避開高危險格子的最短路線（以危險指數加權成本）
6. **AI 視覺化**：系統呼叫 Nano Banana（Gemini 3.1 Flash）在真實課室平面圖上疊加透明熱力色塊和箭頭逃生路線，輸出一張直觀的逃生指引圖
7. **使用者受益**：學生在手機上打開 PWA 網頁，看到即時火焰狀態、熱力圖和 AI 生成的逃生路線圖，沿著綠色箭頭安全撤離；若路線封鎖則顯示避難點並觸發警報和 SOS 通知

### 最終效益
- 學生依清晰路徑在最短時間內安全撤離
- 無法逃生時，系統引導就地避難並通報消防單位，減少傷亡
- 整組系統從感測到出圖全程自動化，不需人工干預

## 4. 技術架構
### 系統組成

| 層級 | 技術/元件 | 說明 |
|------|-----------|------|
| **硬體/感測器** | Arduino Uno + 5×火焰感測器（類比輸入 A0-A4）+ 5×LED（PWM 輸出） | 感測教室內五個位置的火焰強度（0-255 亮度），或以旋鈕模擬火勢變化（Fire_sim.ino） |
| **通訊** | USB 串列通訊 COM3 @ 115200 baud | Arduino → PC 即時數據傳輸 |
| **後端** | Python (FastAPI + uvicorn) | WebSocket 即時推送 + REST API + 數據處理引擎 |
| **資料處理** | NumPy + SciPy (zoom 雙線性插值) | 4×4 → 20×20 網格插值放大 |
| **路徑規劃** | A* 演算法（自實作 heapq）+ 障礙物遮罩 | 20×20 網格動態逃生路徑計算，考慮桌子等障礙物 |
| **AI 模型** | Gemini 3.1 Flash (via APIYi / Nano Banana) | 接收平面圖 + 熱力圖，生成疊加視覺化的逃生路線圖 |
| **前端** | HTML + CSS + JavaScript (Canvas) + PWA | 即時火焰燈動畫、20×20 熱力圖 Canvas 渲染、逃生圖顯示、警報系統 |
| **離線支援** | Service Worker + manifest.json | PWA 可安裝到手機主畫面，支援離線快取 |
| **視覺化** | Matplotlib (後端生圖) + Canvas (前端即時繪圖) | 逃生路線圖、熱力圖、避難圖 |

### 資料流
```
火焰感測器 (×5)
    │ analogRead
    ▼
Arduino Uno ──USB Serial (COM3)──▶ SerialManager (後端)
    │                                   │ 5 個 brightness 值 (0-255)
    │                                   ▼
    │                           FireDataEngine
    │                               ├─ 轉換為 4×4 危險矩陣
    │                               ├─ 雙線性插值 → 20×20
    │                               ├─ A* 路徑規劃 (+ 障礙物遮罩)
    │                               └─ 生成 Matplotlib 熱力圖/逃生圖
    │                                   │
    │                    ┌──────────────┼──────────────┐
    │                    ▼              ▼              ▼
    │              WebSocket 廣播   REST API       Nano Banana AI
    │              (200ms 推送)   /api/generate-*  生成最終視覺圖
    │                    │              │              │
    │                    ▼              ▼              ▼
    │              前端 PWA 即時更新   逃生圖顯示    AI 逃生圖顯示
    │              (火焰燈動畫+熱力圖) (escape_python.png) (nanobanana_result.png)
    │
    └─── 若無法逃生 ──▶ BFS 計算可到達範圍 ──▶ 找出最安全避難點 ──▶ 警報 + SOS + 避難圖
```

### AI 在哪裡發揮作用
- **Nano Banana (Gemini 3.1 Flash Image Preview)**：接收兩張輸入圖（課室平面圖 + 20×20 純熱力圖），在平面圖上疊加半透明熱力色塊和箭頭逃生路線，輸出一張「一看就懂」的視覺化逃生指引圖。這是人類最容易理解的逃生資訊呈現方式，遠比數字矩陣或純程式輸出來得直觀。
- AI 不做決策（路線由 A* 演算法決定），只做**視覺化呈現**，確保路線的正確性和可解釋性。

### 已完成技術
- Arduino 火焰感測器讀取與序列通訊
- 5 感測器 → 4×4 矩陣的加權插值映射
- 雙線性插值放大 4×4 → 20×20
- A* 路徑規劃（含障礙物遮罩，教室桌子區域不可通行）
- BFS 可到達區域搜尋（逃生失敗時找避難點）
- WebSocket 即時數據推送（200ms 間隔）
- REST API（逃生路線觸發、AI 生成、狀態查詢）
- Matplotlib 逃生路線圖 / 避難圖 / 熱力圖生成
- Nano Banana AI 視覺化生成整合
- PWA 前端（火焰燈動畫、Canvas 熱力圖、警報音效 + 震動、SOS 訊息）
- Service Worker 離線支援

## 6. 創新點
- **創新點 1：低成本即時火勢分布感測 + 動態路徑規劃**
  傳統逃生系統只是靜態圖紙或廣播警報，本作品使用 5 個低成本火焰感測器（每顆約 5 元台幣）即可在 4×4 網格上重建火勢分布，透過插值提升至 20×20 精細度，再以 A* 演算法計算**針對即時火勢的最佳逃生路線**。路徑會隨火勢變化動態調整，而非固定路線。

- **創新點 2：逃生/避難雙模式智慧切換 + SOS 機制**
  當 A* 找不到安全路徑時（所有通往出口的路線皆被火勢封鎖），系統不會束手無策。它會以 BFS 搜尋所有「可安全到達」的區域，計算出危險指數最低的格子作為「避難點」，在平面圖上標示並提示使用者就地避難、等待救援。同時觸發手機震動、警報音效，並在畫面上顯示 SOS 求救通知訊息。這是目前市面逃生系統尚未見到的人性化設計。

- **創新點 3：AI 生成式視覺化讓逃生指引「一看就懂」**
  傳統系統輸出的是數字矩陣或純程式路線座標，一般使用者根本無法理解。本作品整合 Nano Banana (Gemini 3.1 Flash) 圖像生成模型，將課室真實平面圖、熱力圖、逃生路線三者合一，產出一張任何人都能秒懂的視覺化逃生指引圖——紅色危險區、綠色安全路線、箭頭方向一應俱全。AI 在此不取代核心演算法決策（路線仍由 A* 保證正確性），而只做「把結果講清楚」的視覺化層。

### 成本與可負擔性
- **硬體成本**（每間教室）：
  - Arduino Uno 相容板：約 200 元
  - 火焰感測器 ×5：約 25 元
  - LED ×5 + 電阻 + 麵包板/PCB：約 50 元
  - USB 線纜：約 30 元
  - **小計：約 300 元 / 間**
- **伺服器**：可用既有學校/辦公室電腦，或便宜的樹莓派（約 1,500 元）
- **AI API 費用**：Nano Banana 每次生成約 0.001-0.005 美金（緊急情況才呼叫，非持續消耗）
- **軟體**：全部使用開源技術（Python, FastAPI, Matplotlib, NumPy），無授權費用
- **結論**：每間教室佈建成本在 500 元以內，遠低於傳統煙霧感測中控系統（數萬至數十萬元）

### 可擴展性 / 產品壽命
- 感測器數量可從 5 個擴充至 n×m 網格，對應更大的空間
- Arduino 可升級為 ESP32，加入 Wi-Fi 無線傳輸，免除 USB 線纜限制
- 可整合多房間聯網架構，透過 MQTT 協定將各教室數據匯集至中央監控儀表板
- 硬體模組為標準 Arduino 生態，零件壽命長、容易更換維修
- AI 模型可隨 Gemini 等模型迭代自動受益於品質提升

## 8. 環保考慮
- **材料**：主要材料為 Arduino 開發板（FR-4 玻纖基板）、火焰感測器（光敏電阻+比較器模組）、LED、麵包板/PCB 及銅導線。全為常見電子元件，無使用稀有金屬或一次性材料。
- **模組重用性**：Arduino 開發板與感測器模組皆可拆卸、重新程式化，用於其他教學或專案，非一次性用途。
- **維修 / 拆卸 / 回收**：感測器採模組化插座連接（麵包板或排針），可單獨更換故障元件。PCB 板依一般電子廢棄物回收管道處理。
- **RoHS / 可回收相關說明**：市面上 Arduino 相容板和標準感測器模組多已符合 RoHS 規範（待確認：需查驗實際採購型號的 RoHS 標示）。建議在採購時優先選擇標示 RoHS 之廠商。
- **減少浪費設計**：系統使用既有教室電腦作為伺服器，不需額外專用硬體。網頁端為 PWA，不需安裝 App，減少裝置儲存和更新維護成本。

- **左欄（傳統方案）**：
  - 靜態逃生平面圖：無法反映火源位置
  - 消防警報：只會響，不告訴你往哪跑
  - 熱像儀系統：造價高昂（數十萬元），無法普及
  - 中控煙霧系統：佈建費用高，需專業安裝
  - 傳統逃生標示：無個人化路線
- **右欄（本作品）**：
  - 即時火勢感測 + 動態路線規劃
  - 視覺化 AI 逃生指引圖，一看就懂
  - 硬體成本 < 500 元/間教室
  - DIY 友善：Arduino 開源生態，容易自建維修
  - 逃生+避難雙模式 + SOS 求救
- **市場與環保要點**：
  - 每間教室成本 < 500 元，遠低於傳統消防系統
  - 模組化設計，零件可更換、可重用
  - 開源軟體棧，無授權費
  - 可規模化：從單間教室擴展到整棟大樓
